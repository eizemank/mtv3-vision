# SeeSharp на модуле MTV3/RV1126: руководство пользователя

Подробное подключение через составной USB gadget, приём CDC ACM, веб-видео и
ADB через USB Ethernet описаны в `docs/MTV3_USB_GADGET_RU.md`.

Пошаговая установка отладочной версии с системной камерой на чистую Ubuntu или
Windows/WSL2 описана в `docs/HOST_CAMERA_SETUP_RU.md`.

Работа конечного пользователя с графическим интерфейсом и пошаговая настройка
детекторов описаны в `docs/DETECTOR_UI_GUIDE_RU.md`.

## 1. Назначение

SeeSharp получает изображение с камеры модуля MTV3, обрабатывает каждый кадр
одним выбранным детектором, рисует результат поверх изображения и передаёт
метаданные внешнему контроллеру или компьютеру.

Доступны режимы:

| `processing_mode` | Назначение |
|---|---|
| `off` | Камера и предпросмотр работают, распознавание выключено |
| `blob_detection` | Цветовые области и составные цветовые объекты |
| `line_detection` | Прямые отрезки |
| `circle_detection` | Окружности |
| `aruco_detection` | ArUco-маркеры |
| `object_detection` | Объекты нейросетью YOLO |
| `classification` | Один класс для всего кадра |

Одновременно работает один детектор. Результат можно получать через веб-интерфейс,
UDP JSON, бинарный UART или составное USB-устройство.

## 2. Первый запуск

### 2.1. Подключение

Подайте питание на модуль и подключите его к сети, настроенной в прошивке. Если
Wi-Fi включён в режиме точки доступа, адрес модуля — `192.168.4.1`. Узнать адрес
при другом подключении можно в списке клиентов роутера или локально командой
`ip addr`.

Откройте в браузере:

```text
http://<адрес-модуля>:8081/
```

На странице доступны исходный кадр, кадр с разметкой, выбор детектора и редактор
параметров. Встроенный сервер не использует HTTPS: подключайте его только к
доверенной локальной сети.

### 2.2. Рекомендуемый порядок настройки

1. Выберите `off` и настройте изображение: поворот, экспозицию, баланс белого,
   контраст и яркость.
2. Выберите нужный детектор.
3. Нажмите **Применить**, чтобы проверить настройки без сохранения.
4. Проверьте результат при минимальном и максимальном рабочем освещении,
   расстоянии и наклоне объекта.
5. Нажмите **Сохранить**, когда результат стабилен.
6. Включите транспорт и проверьте приём на целевом контроллере.

Изменения детектора применяются без остановки захвата кадров. **Применить**
меняет параметры только до перезапуска процесса. **Сохранить** записывает
`config.json`; перед заменой файла создаётся `config.json.bak`. Изменение секции
транспортов требует перезапуска `mainCV` или модуля.

### 2.3. HTTP-интерфейс для автоматизации

| Метод и путь | Результат |
|---|---|
| `GET /` | Веб-интерфейс |
| `GET /config` | Сохранённый JSON-конфиг |
| `POST /apply` | Проверить и применить JSON до перезапуска |
| `POST /config` | Проверить, применить и сохранить JSON |
| `GET /mode/<режим>` | Выбрать и сохранить режим |
| `GET /revert` | Вернуть в память сохранённый конфиг |
| `GET /source.jpg` | Последний исходный JPEG |
| `GET /preview.jpg` | Последний размеченный JPEG |
| `GET /source.mjpg` | Поток исходных кадров |
| `GET /preview.mjpg` | Поток размеченных кадров |
| `GET /metadata/last` | Метаданные последнего кадра (детектор, объекты, FPS) |
| `/training/*` | Сбор датасета, обучение и активация моделей — см. 2.4 |

Пример:

```bash
curl http://192.168.4.1:8081/config -o config.json
curl http://192.168.4.1:8081/mode/aruco_detection
curl -X POST -H "Content-Type: application/json" \
  --data-binary @config.json http://192.168.4.1:8081/apply
```

Если в `system_admin.token` задан токен, изменение самой секции `system_admin`
и административные запросы требуют заголовок авторизации, используемый веб-UI.
Обычные параметры детектора этим ограничением в текущей версии не защищены;
поэтому модуль нельзя публиковать напрямую в Интернет.

### 2.4. HTTP-интерфейс обучения (`/training/*`)

Используется вкладкой **Обучение** веб-интерфейса; пригоден и для скриптов.
По умолчанию открыт так же, как `/config`; при `training.require_admin_token =
true` требует тот же заголовок токена, что и `/admin`.

| Метод и путь | Назначение |
|---|---|
| `GET /training/status` | Датасет (классы, счётчики, квоты), состояние съёмки и тренера, модели, активная модель |
| `POST /training/check` | Проверить Python/PyTorch на устройстве (`training.python`) |
| `POST /training/classes` | `{op: add\|rename\|delete\|display, name, new_name?, display?, confirm?}` |
| `POST /training/capture` | `{class, region_mode?, roi?, blob_pattern_ids?, count, interval_ms}` — снять примеры; `{kind:"yolo", count, interval_ms}` — полные кадры для разметки |
| `POST /training/capture/stop` | Остановить серию |
| `GET /training/samples?class=&offset=&limit=` | Список примеров класса (новые первыми) |
| `GET /training/thumb?class=&file=` | JPEG примера |
| `POST /training/samples/delete` | `{class, files:[…]}` |
| `POST /training/train` | `{epochs?, image_size?}` — запустить обучение классификатора подпроцессом |
| `POST /training/train/stop` | Остановить обучение (SIGTERM, затем SIGKILL) |
| `GET /training/train/log?since=N` | Строки вывода тренера с `sequence > N` |
| `GET /training/models` | ONNX-модели в `training.models_dir` с классами и метриками |
| `POST /training/activate` | `{model, kind?, region_mode?}` — записать модель и классы в конфиг, включить режим, сохранить |
| `GET /training/export?kind=classifier\|yolo` | ZIP датасета (ImageFolder или YOLO с `dataset.yaml`) |
| `POST /training/model` | Загрузка ONNX: тело — файл, заголовки `X-File-Name`, `X-Model-Kind`, `X-Class-Names` (JSON), `X-Input-Size` |
| `GET/POST /training/yolo/*` | Кадры, разметка и классы YOLO (`samples`, `image`, `labels`, `classes`, `delete`) |

Пример полного цикла для классификатора:

```bash
H=http://192.168.4.1:8081
curl -X POST $H/training/classes -d '{"op":"add","name":"ok"}'
curl -X POST $H/training/classes -d '{"op":"add","name":"defect"}'
curl -X POST $H/training/capture -d '{"class":"ok","region_mode":"roi","count":50,"interval_ms":100}'
curl -X POST $H/training/train -d '{"epochs":20}'
curl "$H/training/train/log"
curl -X POST $H/training/activate -d '{"model":"simple_classifier_20260101_120000.onnx","region_mode":"roi"}'
curl $H/metadata/last
```

Датасет лежит в `training.dataset_dir` (по умолчанию `datasets/` рядом с
конфигом): `classifier/<класс>/*.jpg` (ImageFolder), `classifier/index.jsonl`
(откуда вырезан каждый пример), `yolo/images`, `yolo/labels`. Модели — в
`training.models_dir` (`models/`): `<имя>.onnx` и `<имя>.classes.json`.

## 3. Общие параметры изображения

Секция `general_params` применяется до детектора:

```json
"general_params": {
  "processing_mode": "aruco_detection",
  "camera_rotation": 0,
  "ui_language": "ru",
  "exposure_ev": 0.0,
  "white_balance_bgr": [1.0, 1.0, 1.0],
  "contrast": 1.0,
  "brightness": 0.0,
  "debug_mode": false
}
```

| Поле | Значение и влияние |
|---|---|
| `processing_mode` | Активный алгоритм из таблицы выше |
| `camera_rotation` | Поворот по часовой стрелке: только `0`, `90`, `180`, `270` |
| `ui_language` | Язык интерфейса: `ru` или `en`; на распознавание не влияет |
| `exposure_ev` | Программная поправка яркости в ступенях EV; `+1` примерно удваивает значения пикселей, `-1` уменьшает вдвое |
| `white_balance_bgr` | Множители каналов `[B, G, R]`; например `[1.15,1.0,0.9]` усиливает синий и ослабляет красный |
| `contrast` | Множитель контраста; `1.0` — без изменения, больше — контрастнее |
| `brightness` | Добавка к каналам пикселя; положительная осветляет, отрицательная затемняет |
| `debug_mode` | Дополнительная диагностика; формат транспортных данных не меняет |

Сначала стабилизируйте экспозицию и баланс белого. Иначе цветовой детектор будет
требовать слишком широких диапазонов, а нейросеть получит изображения, не похожие
на обучающую выборку.

## 4. Детекторы и их настройка

### 4.1. Цветовые области (`blob_detection`)

Алгоритм переводит BGR-кадр в YCrCb, строит маску по диапазону цвета, находит
внешние контуры и фильтрует их по геометрии. Это быстрый режим для цветных меток,
ламп, деталей и контрастных объектов.

#### Одноцветный шаблон

```json
{
  "id": 10,
  "enabled": true,
  "min_area": 300,
  "max_area": 20000,
  "min_width": 10,
  "min_height": 10,
  "lower_range": [20, 165, 80],
  "upper_range": [240, 210, 130],
  "min_circularity": 0.65,
  "max_circularity": 1.0,
  "min_inertia": 0.4,
  "max_inertia": 1.0,
  "min_convexity": 0.8,
  "max_convexity": 1.0,
  "min_vertices": 0,
  "max_vertices": 0,
  "polygon_approximation": 0.02
}
```

| Поле | Единицы/диапазон | Влияние |
|---|---|---|
| `id` | `0..255` рекомендуется | Идентификатор шаблона в метаданных; должен быть уникальным |
| `enabled` | `true/false` | Отключает только этот цветовой шаблон |
| `lower_range`, `upper_range` | `[Y,Cr,Cb]`, каждый `0..255` | Жёсткие включительные границы цвета |
| `min_area`, `max_area` | пикс² | Площадь контура; отсекает шум и слишком крупный фон |
| `min_width`, `min_height` | пиксели | Минимальный размер осевого bounding box |
| `min/max_circularity` | обычно `0..1` | Округлость `4π·area/perimeter²`; круг близок к `1` |
| `min/max_inertia` | обычно `0..1` | Отношение главных моментов; вытянутые объекты ближе к `0`, симметричные к `1` |
| `min/max_convexity` | обычно `0..1` | `area/area(convex hull)`; вогнутые и рваные контуры имеют меньшее значение |
| `min_vertices`, `max_vertices` | целое | Число вершин аппроксимированного контура; `0` отключает соответствующую границу |
| `polygon_approximation` | доля периметра | Точность аппроксимации; большее значение даёт меньше вершин |

Поля `min_luminance`, `max_luminance`, `min_chrominance_*` из старых конфигов
текущим C++-движком не читаются. Используйте только `lower_range` и `upper_range`.

Практическая калибровка цвета:

1. В веб-интерфейсе удерживайте кнопку мыши и обведите объект замкнутой полилинией на исходном видео.
2. Выберите номер цветового шаблона и нажмите **Настроить blob по выделенному контуру**.
3. Интерфейс вычислит диапазон YCrCb только по пикселям внутри контура и предложит ограничения площади и размера.
4. Проверьте рассчитанные значения и нажмите **Применить** или **Сохранить**.
5. При необходимости расширяйте границы Cr/Cb по 5–10 единиц для устойчивой работы при изменении освещения.
6. После этого корректируйте `min_area`, `min_width`, `min_height`, а геометрические фильтры включайте по одному.

#### Составной цветовой объект

`multicolor_patterns` описывает объект как 1–5 узлов (цветовых областей) и связи
между их центрами. Узел `id: 0` обязателен и является базовым. Первая связь
`id: "0-1"` должна идти первой: относительно неё вычисляются остальные углы и
расстояния.

```json
{
  "id": 20,
  "overall_threshold": 0.65,
  "size_measure": "max_axis",
  "nodes": [
    {
      "id": 0, "blob_id": [10], "threshold": 0.6, "weight": 255,
      "size": {"min": 30, "max": 80, "goal": 50, "weight": 255},
      "circularity": {"min": 0, "max": 1, "goal": 0.8, "weight": 0},
      "inertia": {"min": 0, "max": 1, "goal": 0.8, "weight": 0},
      "convexity": {"min": 0, "max": 1, "goal": 0.9, "weight": 0},
      "angle": {"min": -180, "max": 180, "goal": 0, "weight": 0}
    },
    {
      "id": 1, "blob_id": [11], "threshold": 0.6, "weight": 255,
      "size": {"min": 0.7, "max": 1.3, "goal": 1.0, "weight": 255},
      "circularity": {"min": 0, "max": 1, "goal": 0.8, "weight": 0},
      "inertia": {"min": 0, "max": 1, "goal": 0.8, "weight": 0},
      "convexity": {"min": 0, "max": 1, "goal": 0.9, "weight": 0},
      "angle": {"min": -180, "max": 180, "goal": 0, "weight": 0}
    }
  ],
  "links": [{
    "id": "0-1", "threshold": 0.6, "weight": 255,
    "length_absolute": {"min": 40, "max": 120, "goal": 80, "weight": 255},
    "length_relative": {"min": 0.8, "max": 2.5, "goal": 1.6, "weight": 0},
    "angle_absolute": {"min": -20, "max": 20, "goal": 0, "weight": 255},
    "angle_relative": {"min": -180, "max": 180, "goal": 0, "weight": 0}
  }]
}
```

`size_measure` выбирает размер: `max_axis`, `width`, `height`, `area` или
`convex_area`. В текущей реализации `convex_area` фактически означает площадь
bounding box, а не площадь convex hull.

Для базового узла `size` задаётся в пикселях/пикс². Для остальных узлов это
отношение их размера к размеру узла 0. `length_absolute` — расстояние центров в
пикселях. `length_relative` для базовой связи — расстояние, делённое на размер
узла 0; для остальных связей — длина, делённая на длину связи `0-1`.
`angle_absolute` — угол связи в градусах. `angle_relative` — отличие от угла
связи `0-1`. Угол узла 0 — угол его длинной оси, остальных узлов — отличие угла
их оси от базовой связи.

Каждый критерий имеет:

- `min`, `max` — обязательный допустимый диапазон;
- `goal` — оптимальное значение;
- `weight` — вклад критерия; `0` исключает его из оценки;
- оценку приблизительно `1 - |value-goal|/(max-min)` внутри диапазона.

`threshold` узла/связи — минимальная его средневзвешенная оценка, а
`overall_threshold` — минимальная средневзвешенная оценка всей конструкции.
`weight` самого узла/связи задаёт его вклад в общую оценку. Обычно используют
веса `0` и `255`, хотя математически допустимы и промежуточные значения.

Сначала задайте широкие диапазоны и нулевые веса. Затем настройте размеры,
потом базовую связь, затем остальные связи, и только после этого повышайте
пороги. Число сочетаний быстро растёт с числом найденных цветовых областей;
не оставляйте слишком широкие цветовые диапазоны.

Поля уровня секции:

| Поле | Влияние |
|---|---|
| `enable_one_color_detection` | Предназначен для вывода отдельных цветовых областей; см. ограничение ниже |
| `enable_multicolor_detection` | Поиск составных объектов |
| `max_composite_objects` | Максимум лучших составных результатов, принудительно `1..5` |

> Ограничение текущей версии: `enable_one_color_detection` загружается из JSON,
> но обработчик его не проверяет — отдельные области всё равно попадают в
> результат. Для фактического отключения конкретного цвета задайте `enabled:
> false` у его шаблона; это также исключит цвет из составных объектов.

### 4.2. Линии (`line_detection`)

Алгоритм: grayscale → Canny → вероятностное преобразование Хафа → фильтр угла.

```json
"line_detection": {
  "canny_threshold1": 50,
  "canny_threshold2": 150,
  "canny_aperture_size": 3,
  "canny_l2_gradient": false,
  "hough_rho": 1.0,
  "hough_theta": 0.017453292519943295,
  "hough_threshold": 50,
  "hough_min_line_length": 30,
  "hough_max_line_gap": 10,
  "min_angle": -20,
  "max_angle": 20,
  "roi_x": 0.0, "roi_y": 0.5,
  "roi_width": 1.0, "roi_height": 0.5,
  "max_lines": 20
}
```

| Поле | Влияние |
|---|---|
| `canny_threshold1/2` | Нижний/верхний порог границ; повышение уменьшает шум, но теряет слабые линии |
| `canny_aperture_size` | Размер Sobel-ядра Canny, практически `3`, `5` или `7` |
| `canny_l2_gradient` | `true` точнее считает градиент, но немного дороже |
| `hough_rho` | Шаг расстояния в пикселях; обычно `1` |
| `hough_theta` | Шаг угла в радианах; `π/180` соответствует 1° |
| `hough_threshold` | Минимум голосов за линию; больше — меньше результатов |
| `hough_min_line_length` | Минимальная длина отрезка, пиксели |
| `hough_max_line_gap` | Максимальный разрыв, объединяемый в одну линию, пиксели |
| `min_angle/max_angle` | Допустимый ориентированный угол `-180..180°` |
| `roi_x/y/width/height` | Область поиска как доли ширины/высоты кадра `0..1` |
| `max_lines` | Максимум переданных линий после фильтрации |

Для движения по линии полезно ограничить ROI нижней половиной кадра. Сначала
подберите Canny, затем минимальную длину и разрыв, затем угол.

> Ограничение текущей версии: из-за ошибки загрузчика вместо
> `hough_threshold` в OpenCV передаётся целая часть `hough_theta`. До исправления
> параметр `hough_threshold` фактически не действует, а детектор может выдавать
> слишком много линий. Остальные фильтры, включая `max_lines`, действуют.

### 4.3. Окружности (`circle_detection`)

Перед Hough Circle кадр переводится в grayscale и сглаживается фиксированным
Gaussian Blur 9×9.

| Поле | Влияние |
|---|---|
| `min_radius`, `max_radius` | Допустимый радиус в пикселях |
| `distance` | Минимальное расстояние между центрами; увеличение убирает дубли |
| `hough_param1` | Верхний порог внутреннего Canny; увеличение требует более резкой границы |
| `hough_param2` | Порог центра окружности; меньше — выше чувствительность и больше ложных кругов |

Пример для кругов радиусом 20–60 пикселей:

```json
"circle_detection": {
  "min_radius": 20, "max_radius": 60,
  "distance": 50, "hough_param1": 100, "hough_param2": 30
}
```

Настраивайте в порядке: диапазон радиуса → `distance` → `hough_param2` →
`hough_param1`.

### 4.4. ArUco (`aruco_detection`)

```json
"aruco_detection": {
  "dictionary": "DICT_4X4_50",
  "marker_length": 0.05,
  "allowed_ids": [3, 7, 12],
  "min_area": 100,
  "max_area": 1000000
}
```

`dictionary` должен совпадать со словарём печатного маркера. Поддерживаются
`DICT_4X4_{50,100,250,1000}`, аналогичные `5X5`, `6X6`, `7X7` и
`DICT_ARUCO_ORIGINAL`. Неизвестное имя молча заменяется на `DICT_4X4_50`.
`allowed_ids: []` разрешает все ID; непустой список фильтрует результат.
`min_area/max_area` — площадь четырёхугольника в пикс².

`marker_length` задаётся в метрах, но в текущей версии поза камеры не
вычисляется: параметр сохранён для совместимости, а `pose_rvec` и `pose_tvec`
в JSON равны нулю. Центр и четыре угла передаются в пикселях.

### 4.5. YOLO (`object_detection`)

На MTV3 используется RKNN-модель на NPU. ONNX нужен для настольной сборки и как
исходный артефакт, но не исполняется на модуле.

| Поле | Влияние |
|---|---|
| `model_rknn` | Путь к модели относительно рабочего каталога `/opt/seesharp` либо абсолютный путь |
| `model_onnx` | Модель настольной сборки |
| `class_names_file` | Один класс на строку; порядок обязан совпадать с моделью |
| `class_names` | Имена прямо в JSON; используются вместо/вместе с файлом согласно загрузчику |
| `input_width/height` | Вход модели; обязан совпадать с экспортом RKNN |
| `confidence_threshold` | Минимальная уверенность; выше — меньше ложных и больше пропусков |
| `nms_threshold` | IoU-порог подавления пересекающихся рамок; меньше — агрессивнее удаление дублей |
| `max_objects` | Максимум результатов после NMS |
| `output_layout` | `channels_first` для `[1,A,N]`, `predictions_first` для `[1,N,A]` |
| `output_attributes` | Число атрибутов `A`: `4+classes` либо `5+classes` |
| `output_has_objectness` | `false` для YOLOv8/11, `true` для типичного YOLOv5 |

Пример YOLO11 на 80 классов:

```json
"object_detection": {
  "model_rknn": "yolo11n.rknn",
  "model_onnx": "yolo11n.onnx",
  "class_names_file": "coco.names",
  "class_names": [],
  "input_width": 640, "input_height": 640,
  "confidence_threshold": 0.35,
  "nms_threshold": 0.45,
  "max_objects": 10,
  "output_layout": "channels_first",
  "output_attributes": 84,
  "output_has_objectness": false
}
```

Если объектов много, сначала поднимите `confidence_threshold` с 0.35 до 0.5.
Если одна цель даёт несколько рамок — уменьшайте `nms_threshold`, например с
0.45 до 0.35. Если соседние реальные цели сливаются — увеличивайте его.
Несовпадение layout/attributes обычно даёт отсутствие результатов или
бессмысленные рамки и не исправляется подбором порогов.

### 4.6. Классификация (`classification`)

Классификатор относит область кадра к одному из классов. Область задаёт
`region_mode`:

- `whole` — весь кадр, один результат; при успехе bounding box равен кадру;
- `roi` — фиксированный прямоугольник `roi = [x, y, w, h]` в долях кадра;
- `blob` — каждая рамка, найденная одноцветным blob-детектором (секция
  `blob_detection`, составные объекты не используются). Результатов может быть
  несколько за кадр, по одному на область.

| Поле | Влияние |
|---|---|
| `model_rknn`, `model_onnx` | Модели модуля и настольной/CM5 сборки; относительный путь считается от каталога конфига |
| `input_size` | Квадратный вход модели |
| `resize_size` | Размер короткой стороны перед центральным crop |
| `center_crop` | Сохранить пропорции и вырезать центр; иначе растянуть область в квадрат |
| `swap_rb` | BGR→RGB в настольной сборке; должен совпадать с обучением |
| `mean`, `std` | Нормализация настольной сборки; по 3 значения, `std` не может быть 0 |
| `score_threshold` | Минимальная softmax-вероятность для выдачи результата |
| `class_names`, `class_names_file` | Имена классов в порядке выходов модели |
| `region_mode` | `whole`, `roi` или `blob` |
| `roi` | Прямоугольник для режима `roi` и для съёмки датасета, доли кадра 0..1 |
| `blob_pattern_ids` | Какие одноцветные шаблоны дают рамки; пусто — все включённые |
| `crop_padding` | Отступ вокруг рамки blob (доля её размера); должен совпадать со значением при съёмке датасета |
| `max_regions` | Сколько самых крупных рамок классифицировать за кадр |

В метаданных каждая область даёт запись: `id` — индекс класса, `confidence`
(и `area`) — вероятность, `bbox` — область. Транспортам режим `blob` виден как
несколько записей классификации за кадр.

На MTV3 препроцессинг RKNN должен быть согласован при конвертации модели. Для
штатной модели контракт: RGB, 64×64, нормализация `x/255`.

### 4.7. Обучение на устройстве (`training`)

Секция задаёт, где хранить датасет и модели и чем обучать. Ничего из этого не
выполняется при старте: тренер запускается только по кнопке во вкладке
**Обучение** (или `POST /training/train`), с пониженным приоритетом CPU/IO и
завершается вместе с движком.

| Поле | Значение |
|---|---|
| `dataset_dir`, `models_dir` | Каталоги датасета и моделей (относительно конфига) |
| `python`, `classifier_script` | Интерпретатор с PyTorch и путь к `simple_classifier.py` на устройстве |
| `classifier_epochs`, `classifier_image_size` | Значения по умолчанию для кнопки «Обучить» |
| `jpeg_quality` | Качество JPEG примеров |
| `max_dataset_mb`, `max_samples_per_class`, `max_burst`, `min_burst_interval_ms` | Квоты съёмки |
| `max_upload_mb` | Лимит загрузки ONNX через `/training/model` |
| `require_admin_token` | Требовать админ-токен для `/training/*` |
| `data_yaml`, `base_model`, `epochs`, `image_size`, `output_onnx` | Параметры `train_yolo.py` на хосте |

Если PyTorch на устройстве не установлен, вкладка сообщает причину; датасет
можно скачать zip-архивом, обучить на ПК (`common/nn/simple_classifier.py`
или `board/raspberry-cm5/train_yolo.py`) и загрузить ONNX обратно.

## 5. Транспортные протоколы

Транспорты независимы от детектора и не блокируют обработку: если передатчик не
успевает, сохраняется наиболее свежий ожидающий кадр. `frame_id` позволяет
обнаруживать пропуски.

Доступность в текущей сборке:

| Транспорт | MTV3/RV1126 | Raspberry CM5 |
|---|---:|---:|
| UDP JSON metadata | да | да |
| USB `MTVU` metadata/JPEG | да | да |
| UART binary | да | да |
| UDP fragmented JPEG | нет, секция игнорируется | да |
| UART Dynamixel 1.0 | нет, секция игнорируется | да |
| HTTP UI/JPEG/MJPEG | да | да |

После изменения любого транспорта перезапустите `mainCV`.

### 5.1. UDP JSON metadata

```json
"udp_metadata": {
  "enabled": true,
  "format": "json",
  "host": "192.168.1.50",
  "port": 5000
}
```

`host` — IPv4-адрес получателя, не адрес модуля. Поддерживается только
`format: "json"`. Один обработанный кадр соответствует одной UTF-8 UDP
датаграмме; подтверждения и повторной передачи нет. Максимум — 200 объектов.

Быстрый приёмник:

```bash
nc -u -l 5000
```

Общий объект JSON:

```json
{
  "version": "1.0",
  "msg_type": "detection_frame",
  "frame_id": 123,
  "timestamp_ms": 456789,
  "image_size": [640, 480],
  "detector": "object_detection",
  "inference_ms": 24.5,
  "fps": 30.0,
  "detections": [],
  "aruco_markers": [],
  "lines": [],
  "circles": [],
  "blobs": []
}
```

Всегда присутствуют все пять массивов; заполняется массив активного детектора.
`timestamp_ms` — монотонное время модуля, не Unix epoch.

| Детектор | Элемент результата |
|---|---|
| YOLO/classification | `class_id`, `class_name`, `confidence`, `bbox:{x,y,w,h}`; bbox нормирован к `0..1`, x/y — центр |
| ArUco | `marker_id`, `corners`, `center` в пикселях, нулевые `pose_rvec/tvec` |
| Line | `x1,y1,x2,y2` в пикселях, `angle_deg`, `length` в пикселях |
| Circle | `center` и `radius` в пикселях |
| Blob | `id`, `center` в пикселях, `area` в пикс², `circularity` |

В текущей версии `class_name` в транспортном JSON формируется как `class_N`,
даже если в интерфейсе загружено человекочитаемое имя класса.

Пример Python-приёмника:

```python
import json, socket

s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.bind(("0.0.0.0", 5000))
while True:
    data, sender = s.recvfrom(65535)
    frame = json.loads(data.decode("utf-8"))
    print(frame["frame_id"], frame["detector"], frame["detections"])
```

### 5.2. Бинарный UART

```json
"uart_binary": {
  "enabled": true,
  "device": "/dev/ttyAMA0",
  "baud": 115200,
  "max_objects": 20
}
```

Линия работает в raw-режиме, стандартно 8N1. Поддерживаемые скорости: 9600,
19200, 38400, 57600, 115200 и, если поддержано ОС, 230400, 460800, 500000,
921600, 1000000 бит/с. При неподдерживаемой скорости порт не открывается, а
причина видна в журнале UART TX (`last error`). На CM5 используйте
`/dev/ttyAMA0`: `/dev/serial0` может указывать на отладочный UART.
Изменения секции `transports` применяются без перезапуска `mainCV`.
`max_objects` ограничивается диапазоном `1..20`. Интерфейс модуля использует
уровни 3,3 В; не подключайте его напрямую к 5-вольтовому UART.

Формат пакета, все многобайтовые числа little-endian:

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 2 | `SYNC = AA 55` |
| 2 | 2 | `LEN`, длина только payload |
| 4 | 1 | `MSG_ID` |
| 5 | `LEN` | payload |
| `5+LEN` | 2 | CRC-16/CCITT, little-endian |
| `7+LEN` | 1 | `END = 55` |

CRC считается по `MSG_ID + PAYLOAD`, начальное значение `0xFFFF`, полином
`0x1021`, без финального XOR.

`MSG_ID`: `0x01` off/служебный, `0x02` YOLO или classification, `0x03` ArUco,
`0x04` blob, `0x05` line, `0x06` circle.

Payload header (14 байт):

| Смещение | Тип | Поле |
|---:|---|---|
| 0 | `uint32` | `frame_id` |
| 4 | `uint32` | `timestamp_ms` |
| 8 | `uint16` | width |
| 10 | `uint16` | height |
| 12 | `uint8` | object count |
| 13 | `uint8` | reserved = 0 |

Затем идут записи объектов по 14 байт: `class_id:u8`, `confidence:u8`
(`0..255`), `center_x:u16`, `center_y:u16`, `width:u16`, `height:u16`,
`object_id:u16`, `reserved:u16`. Координаты и размеры — пиксели.

Это унифицированная компактная запись: для линии, окружности и blob часть полей
не передаёт специфические величины (концы линии, точный радиус, площадь). Если
они нужны, используйте UDP JSON или USB JSON. Для ArUco `class_id` содержит ID
маркера, а `confidence` обычно 255.

### 5.3. USB CDC поток `MTVU`

```json
"usb_stream": {
  "enabled": true,
  "device": "/dev/ttyGS0",
  "metadata": true,
  "video": true,
  "jpeg_quality": 80,
  "max_fps": 15,
  "max_width": 960
}
```

На хосте CDC обычно появляется как `/dev/ttyACM0` или `COM<n>`. Поток состоит
из последовательных записей. Заголовок 16 байт использует big-endian:

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 4 | ASCII `MTVU` |
| 4 | 1 | version = 1 |
| 5 | 1 | type: 1 = JSON metadata, 2 = JPEG |
| 6 | 2 | flags = 0 |
| 8 | 4 | frame_id |
| 12 | 4 | payload_size |

После заголовка идёт ровно `payload_size` байт. JSON совпадает с UDP JSON, JPEG
содержится целиком. `frame_id` связывает метаданные и изображение. Качество JPEG
ограничивается `1..100`, `max_width` — `160..1920`, `max_fps` не меньше 1.

Готовый клиент:

```bash
python3 board/raspberry-cm5/usb_stream_receiver.py /dev/ttyACM0
# Windows:
python board/raspberry-cm5/usb_stream_receiver.py COM7
```

Имя каталога клиента историческое; формат подходит и для MTV3.

### 5.4. UDP JPEG (только CM5)

На MTV3 секция `udp_video` в текущей сборке игнорируется. Для CM5 готовый клиент
и полная таблица 32-байтового заголовка находятся в
`board/raspberry-cm5/TRANSPORTS.md` и `udp_video_receiver.py`.

## 6. Диагностика

| Симптом | Что проверить |
|---|---|
| Нет веб-страницы | IP, порт 8081, питание, `/tmp/mtv3.app.log` |
| Есть исходный кадр, нет разметки | `processing_mode`, пороги, модель/словарь, ответ `POST /apply` |
| Цвет плавает | Экспозицию, баланс белого, диапазоны YCrCb при разных условиях |
| UDP не приходит | `host` должен быть адресом приёмника; firewall; транспорт требует рестарт |
| UART молчит | Устройство, общий GND, уровни 3,3 В, одинаковый baud, занятость порта консолью. Откройте журналы UART RX/TX (состояние, счётчики, последняя ошибка) и включите «Режим разработчика» вверху страницы: тесты `uart.port`, `uart.tx_activity`, а с перемычкой TX↔RX — `uart.loopback` |
| YOLO не запускается | Наличие `.rknn`, права, соответствие input/layout/attributes, состояние NPU |
| После перезапуска вернулись параметры | Использовалось **Применить**, а не **Сохранить** |
| Конфиг не применяется | JSON-синтаксис, обязательные поля, диапазон поворота, 1–5 узлов составного объекта |

Логи штатного запуска находятся в `/tmp/mtv3.*.log`. Проверка процессов:

```sh
ps | grep -E 'mtv3_cam_daemon|mainCV'
tail -f /tmp/mtv3.app.log
```

Для безопасного ввода в эксплуатацию сохраните эталонный `config.json`, проверьте
его после холодного старта и записывайте вместе с ним версию модели, разрешение
камеры и условия калибровки. Пороговые значения нельзя переносить между разными
разрешениями без пересчёта пиксельных размеров и площадей.

## 7. Что считать правильной структурой эксплуатации

Рекомендуется разделять конфигурацию на три логических профиля, даже если они
пока хранятся в одном JSON:

1. **Камера** — поворот и коррекция изображения; меняется при монтаже и освещении.
2. **Детектор** — один проверенный набор параметров и версия модели для задачи.
3. **Интеграция** — адреса и настройки транспорта; меняется при подключении к
   другому контроллеру.

Для визуальной настройки удобнее веб-интерфейс. Для основной интеграции с ПК
предпочтителен UDP JSON, для микроконтроллера — бинарный UART, а для одновременной
передачи изображения и метаданных по одному кабелю — USB `MTVU`.
