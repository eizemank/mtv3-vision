# Обучение нейросети через веб-интерфейс SeeSharp

Руководство для оператора: как с помощью вкладки **Обучение** научить модуль
различать свои объекты без ручной работы с файлами и командной строкой.
Описаны два сценария:

- **классификатор** — маленькая сеть 64×64, которая отвечает на вопрос «что
  это?» для кадра или области кадра. Обучается прямо на устройстве (CM5) или
  на ПК;
- **детектор YOLO** — находит объекты и рисует рамки. Разметка делается в
  веб-интерфейсе, обучение — только на ПК.

Общее описание интерфейса и остальных детекторов — в
[DETECTOR_UI_GUIDE_RU.md](DETECTOR_UI_GUIDE_RU.md), параметры конфига — в
[USER_GUIDE_RU.md](USER_GUIDE_RU.md).

## 1. Что нужно заранее

| Что | Для чего |
|---|---|
| Открытый веб-интерфейс `http://<IP-модуля>:8081/` | вся работа идёт в нём |
| Камера, закреплённая так же, как при рабочем использовании | примеры должны быть похожи на то, что сеть увидит потом |
| Для обучения классификатора на устройстве — установленный PyTorch | кнопка **Проверить тренер** показывает, есть ли он |
| Для YOLO — компьютер с Python и `ultralytics` (желательно с GPU) | обучение детектора на модуле не выполняется |

Установка PyTorch на CM5 делается один раз (см. `board/raspberry-cm5/README.md`,
раздел «Neural-network training»):

```bash
sudo apt install -y python3-venv python3-pip
sudo python3 -m venv /opt/seesharp/venv
sudo /opt/seesharp/venv/bin/pip install --index-url https://download.pytorch.org/whl/cpu torch torchvision
sudo /opt/seesharp/venv/bin/pip install onnx pillow
```

Параметры `training.python` и `training.classifier_script` в `config.json` по
умолчанию указывают на этот venv и скрипт `/opt/seesharp/nn/simple_classifier.py`.
Если тренер поставить нельзя, вкладка всё равно собирает примеры, а обучить
можно на ПК (раздел 6).

## 2. Устройство вкладки «Обучение»

Откройте вкладку **Обучение** над редактором параметров. Сверху вниз идут
пять блоков; строка подсказки под заголовком повторяет порядок действий:
«1. Выберите область классификации. 2. Заведите классы и наберите примеры с
камеры. 3. Обучите модель и активируйте её».

| Блок | Назначение |
|---|---|
| **Область классификации** | какая часть кадра попадает в сеть: весь кадр, прямоугольник (ROI) или области, найденные blob-детектором; здесь же строка **Текущий результат** |
| **Классы и примеры** | список классов, счётчики примеров, кнопки съёмки, просмотр и удаление миниатюр |
| **Обучение на устройстве** | проверка тренера, число эпох, кнопки **Обучить** и **Остановить**, прогресс и журнал |
| **Модели** | список обученных и загруженных моделей, **Активировать**, загрузка своего ONNX, ссылки на скачивание датасетов |
| **Разметка YOLO (обучение на ПК)** | съёмка полных кадров, классы YOLO, рисование рамок, выгрузка датасета |

Вкладка опрашивает устройство раз в 1–2 с, поэтому счётчики, прогресс и журнал
обновляются сами. Исходное видео справа остаётся на экране — на нём рисуют ROI
и рамки.

## 3. Шаг 1. Область классификации

Выбор области определяет, что именно вырезается из кадра и для съёмки
примеров, и для распознавания. Поэтому её задают **до** съёмки и после
обучения не меняют.

| Режим | Когда использовать | Что сделать |
|---|---|---|
| **весь кадр** | объект занимает большую часть кадра, положение камеры фиксировано | ничего дополнительно |
| **прямоугольник (ROI)** | объект всегда появляется в одном месте кадра (лоток, зона конвейера) | нажать **Нарисовать ROI на видео**, протянуть прямоугольник мышью по исходному видео, нажать **Взять ROI из выделения**, затем **Применить** или **Сохранить**. Оранжевый пунктир показывает действующий ROI |
| **области от blob-детектора** | объекты разного цвета/формы появляются в разных местах, и их уже находит детектор цветовых blobs | отметить нужные одноцветные шаблоны (или оставить все), включить режим **Цветовые blobs** кнопкой **Включить blob-детекцию**, которая появляется сама, затем **Применить** |

Для режима blob сначала настройте цветовые шаблоны так, чтобы детектор
устойчиво находил объекты (см. руководство по детекторам, раздел 5): сеть будет
классифицировать именно те области, которые он выдаёт.

Параметр `classification.crop_padding` (отступ вокруг области, по умолчанию
10 %) тоже участвует в вырезке. Менять его после съёмки примеров нельзя —
придётся переснимать датасет.

Строка **Текущий результат** показывает ответ активного классификатора, когда
включён режим **Классификация**. До первого обучения там написано, что режим
не активен — это нормально.

## 4. Шаг 2. Классы и примеры

### 4.1. Создание классов

1. В поле **Имя класса (латиница)** введите имя: буквы, цифры, `_`, `-`,
   до 32 символов, например `ok`, `defect_1`, `red_cube`.
2. Нажмите **Добавить класс** (или Enter).
3. Повторите для остальных классов. Нужно **минимум два класса**. Если
   различать надо один объект и «всё остальное», заведите класс `other` или
   `background` и снимите в него пустую сцену и посторонние предметы.

### 4.2. Съёмка примеров

Для каждого класса в строке есть две кнопки:

- **Снимок** — один пример с текущего кадра;
- **Серия N** — N кадров подряд с заданным интервалом. Число кадров и
  интервал в миллисекундах задаются в строке **Серия** над таблицей.

Порядок:

1. Поставьте объект перед камерой так, как он будет выглядеть в работе.
2. Нажмите **Серия** у его класса. В строке состояния видно
   `Съёмка <класс>: сделано/всего, сохранено N`. Кнопка **Стоп** прерывает
   серию.
3. Между сериями меняйте то, что будет меняться в реальной работе: поворот
   объекта, расстояние, освещение, фон, положение в кадре. Так сеть учится
   признакам объекта, а не конкретному кадру.
4. Для режима ROI или blob убедитесь, что в момент съёмки объект находится
   внутри ROI или найден детектором: пример вырезается именно по этой области.
   В режиме blob один кадр может дать несколько примеров — по области на
   каждую найденную blob.

Сколько примеров нужно: для простых задач (несколько хорошо различимых
предметов) достаточно 30–100 на класс. Старайтесь, чтобы у классов было
примерно одинаковое число примеров.

### 4.3. Просмотр и чистка

Кнопка **Примеры** раскрывает миниатюры класса (до 120 последних). Щёлкните по
неудачным (смазанные, пустые, с чужим объектом) — они выделятся красной рамкой —
и нажмите **Удалить выбранные**. **Скрыть примеры** закрывает список.
**Удалить класс** удаляет класс со всеми примерами после подтверждения.

### 4.4. Квоты

Строка над таблицей показывает размер датасета и свободное место. Пределы
заданы в секции `training` конфига и при превышении съёмка не запускается, а
причина выводится под таблицей:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `max_dataset_mb` | 512 | общий размер датасета |
| `max_samples_per_class` | 2000 | примеров на класс |
| `max_burst` | 200 | кадров в одной серии |
| `min_burst_interval_ms` | 50 | минимальный интервал серии |

Датасет хранится на устройстве в `training.dataset_dir`
(по умолчанию `/opt/seesharp/datasets`): папка на класс, файлы JPEG.

## 5. Шаг 3. Обучение на устройстве

1. Нажмите **Проверить тренер**. Зелёная строка «Тренер готов» означает, что
   Python с PyTorch найден. Жёлтая «Тренер недоступен: …» — причина рядом
   (нет Python, не импортируется torch, не найден скрипт); тогда переходите к
   разделу 6.
2. Задайте число **Эпох**. По умолчанию 20 (`training.classifier_epochs`); для
   небольших датасетов этого достаточно, для 500+ примеров на класс можно
   30–50.
3. Нажмите **Обучить**. Кнопка недоступна, пока идёт съёмка или другое
   обучение, и если классов с примерами меньше двух.
4. Следите за полосой прогресса и строкой под ней:
   `идёт обучение: эпоха 5/20, loss 0.31, acc 0.91, val 0.88`.
   - `acc` — точность на обучающей части;
   - `val` — точность на отложенной части (10 % примеров, которые сеть не
     видела при обучении). Именно `val` показывает, как модель поведёт себя в
     работе.
   В журнале ниже — вывод тренера.
5. По окончании строка меняется на «готово», а в блоке **Модели** появляется
   файл `simple_classifier_<дата-время>.onnx` с классами и `val`.
   **Остановить** прерывает обучение; частично обученная модель не сохраняется.

Обучение идёт с пониженным приоритетом, но на CM5 во время него заметно
падает FPS видео — это нормально. Несколько сотен примеров 64×64 на 20 эпох
занимают десятки секунд. Модель и файл классов записываются в
`training.models_dir` (по умолчанию `/opt/seesharp/models`).

Как читать результат:

| Наблюдение | Что делать |
|---|---|
| `acc` высокая, `val` низкая | мало разнообразия в примерах: доснимите с другими ракурсами, освещением, фоном |
| и `acc`, и `val` низкие | классы плохо различимы в выбранной области: сузьте ROI, улучшите свет, увеличьте объект в кадре, добавьте эпох |
| `val` около `1/число классов` | примеры перепутаны между классами или область вырезки пустая; проверьте миниатюры |
| ошибка «PyTorch is not installed» | установите venv (раздел 1) или обучайте на ПК |

## 6. Обучение на ПК (без PyTorch на устройстве)

1. В блоке **Модели** нажмите ссылку **Скачать датасет классификатора (zip)**.
2. Распакуйте архив на ПК. Внутри папка `classifier/` с папками классов и
   `README.txt` с командой.
3. Установите PyTorch на ПК (`pip install --index-url https://download.pytorch.org/whl/cpu torch torchvision onnx pillow`)
   и запустите из корня репозитория:

   ```bash
   python3 common/nn/simple_classifier.py train --data classifier --out models \
       --epochs 20 --image-size 64 --export --stamp
   ```

4. В `models/` появятся `simple_classifier_<ts>.onnx` и
   `simple_classifier_<ts>.classes.json`.
5. В блоке **Модели** выберите файл `.onnx`, тип **classifier 64×64**, при
   желании перечислите классы через запятую (иначе они берутся из обученной
   модели) и нажмите **Загрузить ONNX**. Размер файла ограничен
   `training.max_upload_mb` (по умолчанию 64 МиБ).

## 7. Шаг 4. Активация модели

В блоке **Модели** у каждой модели показаны тип, классы, `val`, размер и дата.
Нажмите **Активировать**:

- в конфиг записываются путь к модели, список классов и размер входа;
- для классификатора также записывается выбранная **область классификации**;
- включается режим **Классификация** (для YOLO — **Объекты YOLO**);
- конфиг сохраняется, перезапуск не нужен.

Активная модель отмечена зелёной точкой. Проверьте работу: строка **Текущий
результат** показывает `класс NN%`, на результате детекции подписывается класс и
уверенность. Порог уверенности — `classification.score_threshold` (по
умолчанию 0,5): ниже него выводится «нет уверенного результата». Поднимите
порог, если сеть уверенно ошибается на пустой сцене; опустите, если правильные
ответы отбрасываются.

Классы не правьте вручную в `class_names`: они берутся из файла модели.
Переименование классов после обучения тоже не нужно — переобучите модель с
новыми именами.

## 8. Детектор YOLO: разметка в интерфейсе, обучение на ПК

Классификатор отвечает «что в области», а YOLO ещё и «где». Для него нужны
рамки на полных кадрах, и обучение выполняется на компьютере.

### 8.1. Классы и кадры

1. В блоке **Разметка YOLO** введите классы через запятую (`cube, ball`) и
   нажмите **Сохранить классы**. Порядок классов важен: номер в списке — это
   номер класса в разметке.
2. Задайте число кадров и нажмите **Снять кадры**: сохраняются полные кадры
   камеры с интервалом не меньше 200 мс. Перемещайте объекты между кадрами.
   Кадры попадают в тот же лимит датасета, что и примеры классификатора.

### 8.2. Рамки

1. Нажмите на имя кадра в списке — он заменит живое видео в левом окне.
2. Выберите **Класс рамки** в выпадающем списке.
3. Протяните прямоугольник мышью вокруг каждого объекта. Жёлтая рамка с
   номером класса остаётся на кадре. **Убрать последнюю рамку** отменяет
   ошибочную.
4. Нажмите **Сохранить разметку**. В списке у кадра появится галочка и число
   рамок. Кадр без объектов тоже полезен: сохраните его с нулём рамок — это
   «фон».
5. **Удалить кадр** убирает кадр с разметкой. **Завершить** возвращает живое
   видео.

Размечайте все объекты нужных классов на каждом кадре: пропущенный объект
учит сеть считать его фоном. Для старта достаточно 50–150 размеченных кадров на
класс при разном положении и освещении.

### 8.3. Обучение и загрузка

1. Нажмите **Скачать датасет YOLO (zip)**. В архиве `yolo/images/`,
   `yolo/labels/`, `yolo/dataset.yaml` и `README.txt`.
2. На ПК установите `pip install ultralytics` и запустите из корня
   репозитория:

   ```bash
   python3 board/raspberry-cm5/train_yolo.py --data yolo/dataset.yaml \
       --epochs 50 --imgsz 640 --base-model yolo11n.pt --out custom_yolo.onnx
   ```

   Скрипт дообучает YOLO11n и экспортирует ONNX в формате, который ждёт
   модуль (opset 12, без встроенного NMS). В конце печатается список классов.
3. В блоке **Модели** выберите `custom_yolo.onnx`, тип **YOLO**, укажите те же
   классы через запятую в том же порядке и нажмите **Загрузить ONNX**.
4. Нажмите **Активировать** — включится режим **Объекты YOLO** с входом 640×640.
   Порог уверенности и NMS настраиваются во вкладке **Параметры детектора**
   (руководство по детекторам, раздел 9).

На CM5 YOLO работает на CPU, несколько кадров в секунду — это ожидаемо.

## 9. Особенности модуля MTV3 (RV1126)

На MTV3 нейросети выполняются на NPU и требуют формата `.rknn`, а не ONNX.
Вкладка **Обучение** собирает датасет и обучает так же, но готовую ONNX-модель
нужно сконвертировать на ПК в окружении rknn-toolkit:

```bash
python onnx2rknn.py simple_classifier_<ts>.onnx dataset.txt      # common/nn/
python onnx2rknn_yolo.py custom_yolo.onnx dataset.txt --size 640
```

и положить `.rknn` на модуль, прописав его в `classification.model_rknn` или
`object_detection.model_rknn`. Подробности — `board/mtv3-rv1126/README.md`.

## 10. Типовые проблемы

| Сообщение или поведение | Причина и решение |
|---|---|
| «Тренер недоступен: python not found» | неверный `training.python`; на CM5 установите venv (раздел 1) |
| «PyTorch is not importable» | в указанном Python нет torch: установите в venv или обучайте на ПК |
| «training.classifier_script not found» | нет файла скрипта по пути `training.classifier_script`; на CM5 это `/opt/seesharp/nn/simple_classifier.py` |
| «at least 2 classes with samples are required» | заведите второй класс и снимите примеры |
| «switch to blob_detection … before capturing blob regions» | для режима blob включите режим **Цветовые blobs** (кнопка в блоке области) |
| «no frames from the pipeline» | нет кадров с камеры: проверьте исходное видео |
| Съёмка отклоняется с кодом 507 | квота датасета (раздел 4.4): удалите лишние примеры или увеличьте лимит |
| «capture is running» / «training already running» | дождитесь конца или нажмите **Стоп** / **Остановить** |
| После активации «нет уверенного результата» | объект вне области, или порог `score_threshold` слишком высок, или область/отступ отличаются от тех, что были при съёмке |
| Модель путает классы после смены ROI или `crop_padding` | съёмка и распознавание должны использовать одну вырезку: верните настройки или переснимите датасет |
| Загрузка ONNX отклонена | имя файла должно оканчиваться на `.onnx`, размер — не больше `training.max_upload_mb` |
| Кнопки вкладки отвечают «unauthorized» | включён `training.require_admin_token`: введите токен в разделе **Системное администрирование** |

## 11. Краткая памятка

1. Закрепить камеру, настроить свет и общие параметры.
2. Выбрать область классификации, для ROI или blob — **Применить**.
3. Завести 2+ класса, снять по 30–100 примеров с разными ракурсами.
4. Просмотреть миниатюры, удалить брак.
5. **Проверить тренер** → **Обучить** → дождаться «готово» и посмотреть `val`.
6. **Активировать** модель, проверить **Текущий результат** в движении.
7. Не менять область и отступ после обучения; при изменении — переснять.
