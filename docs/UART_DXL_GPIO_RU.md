# Проверка DXL UART на GPIO14/GPIO15 CM5

Профиль проверки использует существующую реализацию Dynamixel Protocol 1.0:
заголовок `FF FF`, ID `100` (`0x64`), 115200 бит/с, 8N1, без управления потоком.
Файл спецификации `uart_dxl_protocol_v21.md` внутри содержит заголовок «Версия
2.0». Здесь проверяется его транспорт PING/READ; это не заявление о полной
реализации всех функций спецификации. Ограничения данных детекции описаны в
[TRANSPORTS.md](../board/raspberry-cm5/TRANSPORTS.md).

## Подключение

Используйте USB–UART с логическими уровнями **3,3 В**.

| CM5IO, разъём 40 pin | USB–UART на компьютере |
|---|---|
| GPIO14 / TX, контакт 8 | RX |
| GPIO15 / RX, контакт 10 | TX |
| GND, контакт 6 | GND |

Питание CM5 — штатное; вывод питания адаптера не подключайте. Не подавайте
5 В или уровни RS-232 на GPIO. TX и RX не замыкайте между собой: это проверка
по двум линиям. Для однопроводной шины Dynamixel нужен отдельный согласующий
приёмопередатчик; профиль `rs485=false` предназначен для прямого USB–UART.

## Настройка на CM5

Сборка SeeSharp должна использовать `-DRASPBERRY_CM5=ON`. В корне репозитория:

```bash
sudo systemctl stop seesharp-cm5
sudo sh board/raspberry-cm5/setup_uart.sh
sudo python3 board/raspberry-cm5/configure_uart_dxl.py /opt/seesharp/config.json
sudo reboot
```

Для ручного запуска остановите свой процесс `mainCV` и передайте помощнику
его файл, например `cpp/SeeSharp/build-cm5/config.json`, вместо `/opt/...`.
После перезагрузки запустите приложение обычной командой с камерой.

Скрипт настройки добавляет `enable_uart=1` и `dtoverlay=uart0-pi5` в секцию
`[all]`, удаляет параметры последовательной консоли из `cmdline.txt` и
маскирует `serial-getty` для `serial0` и `ttyAMA0`. Исходные загрузочные файлы
сохраняются с суффиксом `.before-seesharp-uart`.
Назначение GPIO14/15 для overlay подтверждено в
[официальном описании Raspberry Pi](https://github.com/raspberrypi/firmware/blob/master/boot/overlays/README).

Помощник конфигурации включает `transports.uart_dxl` на `/dev/ttyAMA0` и
выключает `transports.uart_binary`, сохраняя прочие настройки. Резервная копия
называется `config.json.before-uart-dxl`. Push включён: при обработке кадров
на TX появляются пакеты без запросов, интервал не менее 33 мс.
На общей шине с другими устройствами используйте `startup_push=false`.

После перезагрузки:

```bash
pinctrl get 14 15
ls -l /dev/ttyAMA0
sudo systemctl start seesharp-cm5
sudo journalctl -b -u seesharp-cm5 --no-pager
```

Ожидаются функции TXD0/RXD0 и сообщение
`UART DXL 1.0: /dev/ttyAMA0 @ 115200`. На CM5 не полагайтесь на `/dev/serial0`:
он может указывать на отдельный отладочный UART. Изменение конфигурации
транспорта требует перезапуска приложения. Для запуска без root нужен доступ
к порту через группу `dialout`.

## Проверка с компьютера

Установите `pyserial` в используемую среду Python и запустите тест на
**компьютере с USB–UART**, выбрав его порт:

```powershell
python -m pip install pyserial
python board/raspberry-cm5/check_uart_dxl.py COM7
```

В Linux можно установить пакет `python3-serial` и передать `/dev/ttyUSB0`.
Закройте другие программы, использующие этот порт.

Тест отправляет PING `FF FF 64 02 01 98`, ожидает
`FF FF 64 02 00 99`, затем читает модель, версию и ID (`READ 0x00, 4`).
Проверяются контрольная сумма, ID, длина ответа и модель `0x5643`.
Фоновый Push игнорируется, настройки модуля тест не меняет. Успех:
`PASS: PING + READ, model 0x5643, ...`. Ошибка даёт код выхода 1.

При тайм-ауте проверьте перекрёстное подключение TX/RX, общий GND, процесс
`mainCV`, настройку порта и журнал. Сохранённые EEPROM-настройки имеют
приоритет над JSON: профиль использует отдельный `dxl_gpio14_15_eeprom.bin`
рядом с конфигурацией. Если ID/скорость уже менялись через DXL, передайте
тесту соответствующие `--id` и `--baud`.

Успешный PING/READ подтверждает транспорт в обоих направлениях. Работу
детектора проверяйте отдельно по Push-пакетам и изображению в веб-интерфейсе.
